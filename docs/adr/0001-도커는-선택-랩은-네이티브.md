# ADR 0001 — Docker 는 선택, 실습 랩은 네이티브로 돈다

- 상태: **채택** (2026-08-18) — 구현 완료
- 맥락: Part 1~2 (정훈) · 대상 = 비개발자 수강생 · 토요일 2시간 오프라인

## 배경

「환경 설정을 통째로 Docker 이미지 하나로 주면 수강생 환경 문제가 사라지지 않나」라는
안이 나왔다. 1회차에서 KIS 공식 Trading MCP 를 쓰려면 Docker Desktop 이 이미 필요하니,
어차피 깔 거면 전부 그 안에 넣자는 논리다.

## 결정

**하지 않는다.** 실습 랩(`agent/` · `src/` · `examples/` · `verify.py`)은 호스트에서
네이티브 Python 으로 돈다. Docker 는 KIS 공식 MCP 를 쓰고 싶은 사람의 **선택 심화**로 둔다.

## 이유

1. **랩은 이미 의존성이 0이다.** 표준 라이브러리만 쓴다(`pyproject.toml` 에 의존성 없음).
   컨테이너가 풀어 줄 「환경 제각각」 문제가 랩 쪽엔 존재하지 않는다.
   macOS 는 `python3`(3.9.6)가 기본 탑재, Windows 는 Store 에서 한 번 클릭이다.
2. **새 seam 이 생긴다.** 수강생의 AI 코딩 도구(Claude Code · Codex CLI)는 호스트에서 돈다.
   랩이 컨테이너 안에 있으면 AI 가 컨테이너 안 파일을 읽고 고쳐야 하고, 그 경로(마운트·
   `docker exec`)를 비개발자에게 설명해야 한다. 줄이려던 설명이 오히려 늘어난다.
3. **실패 반경이 커진다.** 지금은 Docker 가 안 되면 1부 MCP 스텝만 mock 으로 폴백하고
   실습은 계속된다. 랩까지 컨테이너에 넣으면 Docker 실패 = 수업 전체 정지다.
   Docker Desktop 은 비개발자에게 가장 어려운 설치다(WSL2 · 수 GB · 관리자 권한).
4. **토요일엔 어차피 값이 안 온다.** 수업일은 휴장이라 공식 MCP 를 띄워도 시세·주문이
   막힌다. 가장 비싼 설치가 그날 가장 적은 것을 돌려준다.

## 그럼 1부 MCP 실습은

랩 안에 **stdio MCP 어댑터**를 둔다(표준 라이브러리 JSON-RPC, `src/common/kis.py` 재사용).

- 등록이 한 줄이고 포트·tar·컨테이너 재시작 문제가 없다.
- 토요일에도 mock 으로 답하므로 실습이 멈추지 않는다.
- 노출 도구를 `검색` · `상세보기` · `호출` 3개로 맞추면
  `lessons/0-시작/2-개념-정보전달과-MCP.md` 가 설명한 catalog(점진적 공개)를 그대로 체험시킨다.
- 1부에서 붙인 어댑터를 2부 `agent/agent.py` 가 같은 `KISClient` 로 재사용해,
  두 회차가 하나의 seam 으로 이어진다.

공식 Trading MCP(330개 API)는 「진짜 catalog 를 실물로 보고 싶은 사람」을 위한 심화로
`lessons/참고/kis-mcp-연동-가이드.md` 에 남긴다. 강사 시연은 이쪽으로 한다.

**구현됨 (2026-08-18)**: `agent/mcp_server.py`. `claude mcp list` 에서 연결 확인,
Python 3.9 통과, `verify.py` 5번째 점검으로 회귀 방어.
수업 경로를 하나로 유지하려고 트러블슈팅 스킬의 Docker 항목 5개(#5·6·7·9·10)를
「수업 중엔 안 씁니다」 섹션 아래로 격리했다 — 선택지를 열면 환경이 갈라지고
트러블슈팅이 환경마다 필요해지기 때문이다.

**기능 차이는 남는다**: 공식 330개 vs 우리 2개, 그리고 공식은 **주문 API 도 노출**한다.
주문 노출은 없는 게 맞다 — 이 수업은 가드레일을 통과한 주문만 `agent.py` 가 실행하는데,
MCP 로 AI 가 직접 주문하면 가드레일을 우회한다(`AGENTS.md` 규칙과 충돌).
「실제 KIS 에 붙는다」는 `KIS_MODE=live` 로 동일하다 — 잃는 건 API 개수뿐이다.

## 되돌리는 조건

- 랩에 외부 의존성이 생겨 설치가 실제로 갈리기 시작하면 재검토한다.
- 수강생 다수가 Python 설치 자체에서 막힌다는 실측이 나오면 재검토한다
  (현재 가설: macOS 기본 3.9.6 으로 충분 — `requires-python` 을 3.9 로 낮추는 건 별건).
