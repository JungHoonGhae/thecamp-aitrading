# 설계: repo 구조 단일 진입 + Part 1/2 명확화 재편

작성 2026-07-07. 목표: 산발적 구조를 "파일 하나 열면 다음다음으로 이어지는" 단일 진입
학습 경로로 정리. **Part 1 / Part 2를 명확히 나누고, 각 파트가 목표·성취·실습을 먼저
선언**. 파일명 넘버링. 학생/강사/참고/발표/코드를 층으로 분리.

## 문제
- 최상위에 학습 폴더·참고문서(docs/ 8개)·코드·발표·강사자료가 같은 층위에 섞여
  "어디부터, 다음 어디로"가 불명확.
- 핵심 **개념 문서**가 docs/에 묻혀 학습 순서에서 빠져 보임.
- **Part 1/2 구분이 약함**: 자동화가 `3-자동화`로 최상위에 있어 마치 3회차처럼 보임
  (실제론 2회차=Part 2의 마지막 단계). 파트별 "무엇을 달성하는지"가 앞에 안 나옴.

## 원칙
1. 학습 경로(스파인)를 번호로 한 줄 세우고, 나머지(참고·발표·코드·강사)는 층 분리.
2. **딱 두 파트**로 나눈다: Part 1(연결, 1회차) / Part 2(나만의 에이전트, 2회차).
   자동화는 Part 2의 마지막 스텝. (정훈 담당은 2회차뿐 — 3~4회차는 문상록)
3. 각 파트 README는 **목표 → 끝나면 할 수 있는 것 → 직접 하는 실습/수정 → 스텝 목록**
   순으로 먼저 선언한다.
4. 스파인의 모든 파일 하단에 이전/다음 내비게이션.

  2-스펙-수정.md                (내가 원칙을 고침 + 가드레일 체험)

## 각 파트 README 형식 (신규 — 핵심 요구)
```
# {N}부 · {제목} ({회차})
## 이 파트의 목표         — 한 문장. "무엇을 달성하는가"
## 끝나면 할 수 있는 것    — 불릿 3~4개. "이 정도까지 할 수 있다"
## 직접 하는 것 (실습)     — 받아서 실행 → 내가 수정 → 다시 실행 → 공유. "본인이 고치는" 것 명시
## 스텝                   — 번호 목록(각 스텝 파일 링크)
## 준비/주의             — mock 폴백·휴장 등
→ 다음: {다음 파트/마무리}
```
- Part 1 목표 예: "AI를 실제 시장에 연결한다." 성취: 데이터 소스 연결 원리·KIS 모의계좌
  실제 조회·MCP 판단 기준.
- Part 2 목표 예: "내 원칙을 선언하면 스스로 점검·리밸런싱·보고하는 나만의 에이전트."
  성취: 스펙으로 원칙 선언·가드레일 설계·모의 리밸런싱·정기 자동 실행.

## "다음다음" 장치
1. **단일 진입**: 루트 README → "▶ 0-시작/README.md".
2. **스텝 하단 내비**: 모든 스텝 .md 끝에 `◀ 이전 · 다음 ▶`. 부 경계도 자동으로 넘어감.
3. **부 README**: 위 형식(목표·성취·실습·스텝·다음).

## 주요 결정과 근거
- **딱 두 파트 + 자동화는 Part 2 스텝**: 정훈 담당 = 2회차. 최상위 "3-자동화"가 3회차처럼
  보이는 오해 제거.
- **개념·환경세팅을 스파인 안으로(0-시작)**: 산발적 원인 해소.
- **참고/발표자료 분리**: 학습 순서에 안 섞이게.
- **강사용 분리 유지 + 구조 미러**: 통합 시 공개 repo에 강사 전용 노출·혼선. teacher/를
  같은 파트 구조로 미러, 단일 진입 teacher/README.md.
- **코드는 각 부 루트에**: 스텝(.md)과 코드 같은 폴더. `common/`은 import 이름이라 유지.
- **넘버링**: 대단원 `0 / 1부 / 2부 / 9`, 하위 스텝 `1-,2-,3-,4-`.
