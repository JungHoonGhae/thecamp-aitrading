# 3 · Telegram에서 분석과 모의주문 직접 실행

## 가설은 매번 세우지 않습니다

앞 단계에서 후보 선정 가설의 쓰임과 약점을 확인했습니다. 실제 주문 규칙은 사람이
`내-투자-스펙.md`에 채택해 둔 목표입니다. 이제부터는 그 규칙 안에서 계좌를 점검하고 주문
계획을 확인합니다.

```text
처음 설계할 때만  문제의식 → 후보 가설 → 근거·약점 확인 → 사람이 목표 저장
평소 반복          현재 규칙 → 주문 계획 → 사람 승인 → 연습 체결 → 기록
```

노트북에서는 Hermes gateway가 텔레그램에 연결돼 있습니다. 학생은 폰에서 직접 명령을
보내고 버튼을 누릅니다. Claude나 Codex가 없어도 계좌 조회와 규칙 계산은 그대로 동작합니다.

## 0. 시작 화면

내 투자 에이전트에 아래를 보냅니다.

```text
/ts_help
```

`/ts_help`, `/ts_update`, `/ts_doctor`, `/ts_auth`, `/ts_status`, `/ts_tools`, `/ts_config`,
`/ts_analyze`, `/ts_rule`, `/ts_order_plan`, `/ts_memory`가 보이면 준비됐습니다. 그 아래 Hermes 기본
명령이 함께 보이는 것도 정상입니다.

강사가 수업 중 자료를 바꿨다고 하면 `/ts_update`를 한 번 보냅니다. 학생의 `.env`·스펙·판단
기록·계좌 설정·연습 장부는 자동으로 보존됩니다. 업데이트 뒤 `/ts_doctor`가 모두 ✅이면
원래 단계로 돌아옵니다. 로그인 경로만 따로 보려면 `/ts_auth`를 사용합니다.

## 1. 계좌·보유 주식·대기 주문 읽기 · 3분

```text
/ts_status
```

잔고·보유 주식·대기 주문이 한 답장에 바로 나옵니다. 이 명령은 모델과 선택 버튼 없이 지금
선택한 계좌를 읽습니다. 기본은 휴장에도 움직이는 **수업용 계좌**입니다. KIS 모의투자 키를 준비한 사람만
`/ts_config`에서 **KIS 모의투자 계좌**로 바꿀 수 있습니다. 둘은 서로 다른 계좌이며 실계좌
선택지는 없습니다. AI를 호출하지 않고 주문도 만들지 않습니다.

## 2. 기술적 분석 읽기 · 3분

토요일이라 장이 닫혀 있어도 과거 가격은 읽을 수 있습니다.

```text
/ts_analyze AAPL
```

`기술적 분석` 버튼을 누릅니다. 내 투자 에이전트는 1년 가격 변화, 20일·60일 평균과의 거리,
흔들림, 1년 고점과의 거리, 같은 기간 S&P500과의 차이를 먼저 계산합니다. 국내 종목은
`/ts_analyze 삼성전자`처럼 보내면 코스피와 견줍니다.

이 기본 계산에는 AI가 필요하지 않습니다. 이어서 Claude 또는 Codex가 우선 검토하고, 둘 다
쓸 수 없으면 Hermes의 무료 모델이 최종 의견을 붙입니다. 실제로 답한 AI 이름을 표시하며,
모두 실패해도 기본 계산은 남습니다. Yahoo Finance 시세는 학습용 조회 경로로만 읽고 주문
계산에는 사용하지 않습니다. 같은 내용의 PNG 미리보기와 모바일 HTML 보고서도 함께 옵니다.

### 2-1. 지표 하나를 추가하고 전·후 비교 · 5분

먼저 위 기본 결과에 `20일 평균보다`, `60일 평균보다`가 있는지 봅니다. 그다음 아래처럼
버튼을 누릅니다.

```text
/ts_config
→ 기술적 분석 지표
→ 5일선 추가
```

다시 같은 `/ts_analyze AAPL`에서 `기술적 분석`을 고릅니다. 결과에 `5일 평균보다` 한 줄이
추가되면 성공입니다.

```text
BEFORE  20일선 · 60일선
AFTER   5일선 · 20일선 · 60일선
```

종목과 데이터는 같고 표시 지표만 하나 늘었습니다. 현재 규칙·가드레일·계좌·주문 계획은
바뀌지 않습니다. 기본 화면으로 되돌리고 싶으면 같은 메뉴에서 `기본 · 20일선·60일선`을
누릅니다.

## 3. 펀더멘탈 분석 읽기 · 4분

```text
/ts_analyze AAPL
```

이번에는 `펀더멘탈 분석` 버튼을 누릅니다. Hermes가 가능한 AI 작업자를 골라 회사 IR, 한국
기업은 DART, 미국 기업은 SEC 자료를 우선 찾습니다. 사업이 돈을 버는 방식, 최근 재무의
방향, 다음에 확인할 위험과 원문 주소를 짧게 돌려줍니다. `둘 다 분석` 버튼을 누르면 기술적
분석과 펀더멘탈 분석을 모아 마지막 종합 의견까지 볼 수 있습니다.

공식 자료를 찾지 못하거나 AI가 미설치·로그인·한도 문제로 실행되지 않으면 그 상태를 말하고
내용을 지어내지 않습니다. 이 결과도 읽기 전용이며 주문과 연결되지 않습니다.

## 4. 저장된 규칙 확인 · 3분

```text
/ts_rule
```

`현재 규칙` 버튼을 누릅니다. 내 투자 에이전트는 처음 한 번 채택한 규칙을 보여 줍니다.

- KIS 모의계좌라면 사람이 채택한 국내 다섯 종목과 목표 20%
- 목표와 현재 비중이 5%p 이상 벌어지면 조정 후보
- 한 종목 최대 40%, 현금 최소 5%
- 가드레일 위반 시 주문 차단, 사람 승인 전에는 주문 없음

이 단계에는 AI 판단도 주문도 없습니다. 저장된 시스템 규칙을 읽는 화면입니다.

수업용 계좌를 선택했다면 고정 수업 바스켓 규칙이 나옵니다. KIS 모의계좌와 수업용 계좌는
서로 다른 계좌이므로 현재 선택은 `/ts_config`에서 먼저 확인합니다.

## 5. 정확한 주문 계획 보기 · 4분

```text
/ts_order_plan
```

규칙 코드가 저장된 규칙과 현재 선택 계좌를 비교해 주문 계획을 만듭니다. 화면에서
네 가지를 읽습니다.

1. 어떤 종목인가
2. 매수인가 매도인가
3. 몇 주인가
4. 지정가는 얼마인가

내부 계획 번호는 종목·방향·수량·지정가를 한 묶음으로 잠그지만 학생 화면에는 노출하지
않습니다. 아래 명령을 한 번 더 보내면 방금 계획이 승인 대기 중인지 확인할 수 있습니다.

```text
/ts_status
```

`대기 주문` 버튼을 누릅니다.

## 6. 사람의 주문 승인 · 4분

계획 아래 버튼 가운데 하나를 누릅니다.

- **이 계획 승인** — 저장된 계획과 내부 번호가 완전히 같을 때만 선택한 모의계좌에서 한 번 실행
- **보류** — 주문 없이 끝냄

글로 “승인”이라고 보내서는 실행되지 않습니다. 텔레그램의 승인 선택은 2분 뒤 자동
보류되며 한 번 실행한 버튼은 다시 쓸 수 없습니다. 시간이 지나면 `/ts_order_plan`을 다시 보냅니다.

선택한 KIS 모의계좌에서 승인하면 아래처럼 국내 종목 코드와 증권사 모의
주문번호가 함께 나옵니다. 실제 수량은 계좌 상태와 시세에 따라 달라집니다.

```text
[주문 전송] KIS 모의투자 계좌 · 3건

매수 삼성전자 (005930) 1주 · 주문번호 00000001
매수 SK하이닉스 (000660) 1주 · 주문번호 00000002
매수 현대차 (005380) 1주 · 주문번호 00000003

같은 승인 버튼은 다시 사용할 수 없습니다.
증권사 모의 서버에 보낸 주문이며 실계좌 주문이 아닙니다.
```

실제 돈은 움직이지 않습니다.

승인 뒤 `/ts_status` 한 번으로 보유 종목이 생겼는지와 승인 대기가 사라졌는지 함께 확인합니다.

## 7. 자동 기록을 열고 필요한 원칙만 기억하기 · 2분

분석·설정·계획·승인·보류는 현재 Hermes 세션에 자동으로 남습니다. 매번 일지를
쓰지 말고 먼저 자동 기록을 열어 봅니다.

```text
/ts_memory
```

Hermes가 자동으로 남긴 활동, 현재 규칙과 계좌, 오래 기억하는 선호를 구분해 보여 줍니다.
앞으로도 반복할 원칙이 있을 때만 아래처럼 선택적으로 남깁니다.

```text
/ts_memory 기술주 합계 비중은 40%를 넘지 않게 기억해 줘
```

같은 뜻으로 “이건 기억해 줘”라고 자연어로 말해도 됩니다. 오늘 한 번의 감상은
세션에 이미 남으므로 영구 Memory에 중복 저장하지 않습니다. 예전 `/ts_log` 입력도 호환됩니다.

## AI 검토가 필요할 때만

평소 주문마다 가설을 다시 검증하지 않습니다. 시장이나 내 생각이 크게 달라져 **현재 규칙을
다시 검토할 때만** 아래처럼 돌아갑니다.

```text
/ts_rule 큰 하락장에서 이 규칙이 약한지 다시 보고 싶어
```

`가설 근거와 약점` 버튼을 누릅니다. 이 명령은 고정된 수업 예제의 근거와 약점을
다시 읽는 검토 화면이며, 현재 규칙이나 포트폴리오는 바꾸지 않습니다.

## 같은 화면 안에서도 역할은 다릅니다

| 화면 | 실제로 일한 층 |
|---|---|
| 기술적 분석의 기본 지표 | 규칙 코드 + Yahoo Finance 시세 |
| 기술적·펀더멘탈·시장 분석의 최종 의견 | Hermes가 연결한 Claude · Codex · 무료 모델 |
| 현재 규칙 | 사람이 저장한 목표 포트폴리오와 가드레일 |
| 종목·수량·지정가 | 규칙 코드 |
| 승인·거절·기록 | 사람 |
| 명령과 버튼 | 텔레그램 |
| 체결 | 선택한 수업용 계좌 또는 KIS 모의투자 계좌 |
| 규칙을 다시 검토할 때의 약점·반대 근거 | Hermes가 연결한 Claude · Codex · Nous 무료 모델 |

텔레그램 한 화면에 함께 보인다고 같은 주체가 결정한 것은 아닙니다.

## 문제가 생기면

- `/ts_rule`의 현재 규칙이 예상과 다름 → `/ts_config`에서 선택 계좌를 먼저 확인합니다.
- 버튼을 눌러도 늦었다고 나옴 → `/ts_order_plan`로 새 계획을 만듭니다.
- 이미 실행됐다고 나옴 → 같은 버튼의 재사용을 막은 정상 동작입니다.
- 폰에서 답이 없음 → 노트북에서 Hermes gateway 연결 상태를 봅니다.
- `Searching files...`처럼 오래 찾기 시작함 → 설치된 수업 플러그인이 예전 버전일 수 있습니다.
  코딩 앱에 `python hermes/setup_course.py --from-project-env 를 실행해 줘`라고
  보냅니다.
- 버튼을 고르던 중 다른 명령이 막힘 → `/stop`을 보내 대기를 끝내고 원래 명령을 다시 보냅니다.

## ☑️ 넘어가도 되는 신호

- 수업의 고정 예제는 필요할 때만 근거·약점을 다시 읽고, 매 주문마다 채택하지 않는다고 설명할 수 있습니다.
- `/ts_status`의 잔고·보유 주식·대기 주문이 같은 선택 계좌를 읽는 것을 확인했습니다.
- `/ts_config`에서 5일선을 켜고 같은 분석의 전·후를 비교했습니다.
- `/ts_status`의 대기 주문에서 승인 전과 승인 뒤 상태가 달라지는 것을 확인했습니다.
- `/ts_analyze`의 기술적 분석이 기본 지표와 실제 AI 작업자 이름을 보여 주며 주문과 분리돼 있습니다.
- `/ts_analyze`의 펀더멘탈 분석이 공식 자료의 원문·기준일을 요구하고 주문과 분리돼 있습니다.
- `/ts_rule`에서 이미 저장된 규칙을 확인했습니다.
- `/ts_order_plan`의 종목·방향·수량·지정가를 읽었습니다.
- 버튼 승인 뒤에만 선택한 모의계좌가 움직였습니다.
- `/ts_memory`로 자동 활동과 본인의 판단을 구분해 돌아봤습니다.
