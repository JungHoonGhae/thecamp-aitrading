# 아키텍처 한눈에 보기

## 학습 흐름 (학생 여정)
```mermaid
flowchart LR
    A[README<br/>여기부터] --> S0[0-시작<br/>환경·개념]
    S0 --> C1[1부·1<br/>직접 호출]
    C1 --> C2[1부·2<br/>MCP 연결]
    C2 --> D1[2부·1<br/>예제 실행]
    D1 --> D2[2부·2<br/>스펙 수정]
    D2 --> D3[2부·3<br/>재실행·리밸런싱]
    D3 --> H[2부·4<br/>자동화 예약]
    H --> E[9-마무리<br/>신뢰 게이트]
```

## 데이터 흐름 (에이전트가 하는 일)
```mermaid
flowchart TD
    S[agent/spec 마크다운<br/>목표비중·규칙·한도] --> AG[agent.py]
    K[common/kis.py] --> AG
    K -->|mock 기본| FX[(fixtures<br/>키·휴장 무관)]
    K -->|live 선택| API[KIS 모의투자 API]
    AG -->|현재 vs 목표 비교| PV[리밸런싱 미리보기]
    PV -->|가드레일 통과 + --execute| ORD[모의 주문<br/>place_order]
    PV -->|위반 시| BLK[주문 차단]
    ORD --> K
    AG --> REP[common/report.py<br/>Report 구조체]
    REP --> TG[common/telegram.py]
    TG -->|토큰 있으면| TELEGRAM[텔레그램]
    TG -->|없으면| SCR[화면 stdout<br/>to_plain_text]
```
> `Report`는 데이터클래스다 — telegram.py는 agent.py가 만든 문구를 다시 파싱하지 않고,
> Report의 필드를 그대로 서식만 입혀 렌더링한다(텔레그램·화면이 같은 Report를 공유).
> 기본은 미리보기(주문 없음). `--execute` + 가드레일 통과 시에만 모의 주문. 실계좌 아님.

## 자동화 — 같은 에이전트를 깨우는 방법
```mermaid
flowchart LR
    subgraph 본편["hermes-agent (2회차 목적지, Nous 무료 로그인)"]
      direction TB
      CRON["예약 --no-agent<br/>portfolio-check.py"]
      CHAT["채팅 '점검해줘'<br/>skills/portfolio-check"]
    end
    FB[폴백: OS crontab<br/>같은 agent.py]
    CRON -->|정해진 시각| RUN[agent/agent.py]
    CHAT -->|즉시| RUN
    FB --> RUN
    RUN --> TG[common/telegram.py]
    TG --> TELEGRAM[텔레그램]
```
> 실행(`agent.py`)과 보고(`telegram.py`)는 같고, 깨우는 방법만 다릅니다.
> 판단(스펙 인터뷰·리뷰어)은 Claude Code, 자는 동안 깨우기는 hermes.
> 설치가 막히면 crontab 한 줄이 폴백입니다.
