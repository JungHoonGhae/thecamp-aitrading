패스트캠퍼스 · Part 1~2 / 정훈

AI 자동매매
시스템 제작

AI를 국내 주식시장(KIS 모의투자)에 연결하고, 내 원칙을 스펙으로 선언해 스스로 점검·리밸런싱하는 나만의 에이전트를 만든다.

오늘의 약속

코딩을 몰라도,
끝나면 동작하는 시스템이 남는다

  • 1회차 — AI가 내 모의계좌를 실제로 조회하게 연결
  • 2회차 — 스펙을 선언하면 가드레일 안에서 리밸런싱 + 디스코드 보고
  • 실습은 "프롬프트 복사 → 붙여넣기"에서 시작

개념 / 01

정보는 양이 아니라
구조로 전달한다

발표를 토씨 하나까지 외우면 오히려 막힙니다. 잘하는 사람은 핵심 키워드만 쥐고, 나머지는 그 자리에서 추론해 연결합니다.

개념 / 02

“스타필드 안 A 레스토랑으로 와”

모든 골목을 안 읊어도 친구는 찾아옵니다 — 사람이니까요. AI 모델도 추론합니다. 목적지와 길 찾는 능력만 주면 됩니다.

개념 / 02.5 · 생각의 흐름

친구의 머릿속 = AI의 머릿속

낯선 몰에서 친구는 키오스크로 검색 → 몇 층인지 확인 → 찾아갑니다. AI도 도구 3개로 “내 잔고 얼마야?”의 길을 똑같이 냅니다.

친구 · 스타필드

① 키오스크에서 “A 레스토랑” 검색
② 몇 층 몇 호·가는 길 확인
③ 그 층으로 가서 도착

AI · MCP 도구 3개

① 검색 — “잔고” 관련 API 찾기
② 상세보기 — 파라미터·필요조건 확인
③ 호출 — 실제 잔고 조회

개념 / 02.7 · 여러 갈래

처음 보는 곳이어도
길은 여러 갈래

스타필드가 없던 시절 처음 가도 — “대형 몰이면 키오스크가 있겠지”, 없으면 “인포메이션에 물어보지”. 세부 지시가 없어도 도달하는 길은 많습니다.

그래서 정보를 다 쏟으면
오히려 헷갈립니다.

개념 / 03 · 문제

문서 330개를 통째로 던지면?

토큰 폭발

수십만 토큰 → 비용도, 남는 공간도 없음

정확도 하락

중요한 게 묻혀 엉뚱한 값을 지어냄(환각)

문서 ≠ 실행

인증·계좌 처리는 문서만으론 안 됨

금방 낡음

복붙한 순간부터 원본과 어긋남

개념 / 04 · 해법

MCP = 필요할 때 필요한 것만
(catalog · 점진적 공개)

검색→ 상세보기→ 호출 ··· 필요한 스펙만 그때 로드

평소엔 도구 3개만. “잔고가 필요하네” 하면 그 스펙만 꺼냅니다.

개념 / 05 · 위계

무엇이 위에 있는 정보인가

기반 인증 · 계정 — 모든 것이 여기에 의존
그 위에 계좌
그 위에 종목
그때 상세 파라미터 — 필요할 때만

상위 정보를 먼저, 세부는 필요할 때. 이 감각이 실력입니다.

개념 / 06 · 재사용

서버 하나, 어디서든 — N×M → N+M

같은 MCP를 Claude Code에도, hermes에도 붙입니다. 소스마다·도구마다 따로 잇던 걸, 서버 하나로 모두가 재사용합니다.

개념 / CLI vs MCP

정해진 반복은 CLI,
그때그때 판단은 MCP

CLI = 자판기

정확한 버튼을 누르면 정해진 게 딱. 매번 똑같은 일엔 제일 빠르고 확실 — 대신 버튼에 없는 건 안 됨

MCP = 점원

“이런 게 필요해요” 하면 알아서 처리. 뭐가 필요할지 모를 때·여러 앱에서 재사용할 때 유리

CLI는 강력한 만큼 위험(잘못 치면 파일이 지워질 수도)해서, 오늘은 “이런 것도 있다”만 짚고 넘어갑니다.

1회차 / 연결

환경 세팅조차 AI가 한다

사전 준비만 손으로. 나머지는 프롬프트를 붙여넣으면 AI가 설치합니다.

📋 “이 저장소를 실행할 수 있게 내 환경을 세팅해줘”
  • python verify.py → mock 4/4 확인

1회차 / MCP 연결

AI가 내 모의계좌를 실제로 조회

📋 “모의투자로 삼성전자 현재가 알려줘”

KIS 공식 Trading MCP를 붙이면, AI가 국내 주식(KIS 모의투자) 데이터를 가져옵니다.

1회차 / 왜 Docker

노트북이 다 달라도 똑같이 돈다

MCP를 컨테이너(Docker)로 주는 이유 = 환경 통일. 누구 컴퓨터에서든 같은 결과.
Docker가 안 되면? mock 폴백으로 동일하게 경험합니다.

1회차 / 유지보수

도구가 깨지면, AI가 고친다

라이브러리가 바뀌면 공식 도구도 깨집니다. 예전엔 사람이 밤새 고쳤죠. 이제는 AI가 증상을 보고 원인을 찾아 수리합니다 — 유지보수의 자동화.

Part 2

나만의 AI
투자 에이전트

연결 위에서, 내 원칙대로 점검 → 리밸런싱 → 보고.

2회차 / 예제 실행

먼저 그대로 돌려본다

보유한 계좌라 매수·매도 신호가 섞여 나옵니다 = 리밸런싱의 핵심.
단, 예제는 정답이 아니라 검증 중인 가설(예시)입니다.

2회차 / 스펙 선언

코딩이 아니라 선언

마크다운 몇 줄로 종목·비중·주기 + 가드레일을 정합니다.

📋 “portfolio.md의 비중을 이렇게 바꿔줘 … 한 종목 최대 40%”
  • 일부러 45%로 올려 경고를 체험 → 되돌리기

2회차 / 리밸런싱

신뢰 게이트를 코드로

① 미리보기→ ② 가드레일 통과분만→ ③ 확인 후 모의 주문

가드레일을 넘으면 주문 자체를 막습니다. 실행은 명시적으로 켤 때만.

2회차 / 자동화

hermes에 말로 예약한다

📋 “매주 월 8시에 no-agent로 실행해 디스코드로 보내줘”

예약 기능이 내장돼 있어 명령을 외울 필요가 없습니다. 자는 동안 AI가 시장을 지켜봅니다.

마무리

신뢰는 한 단계씩

읽기전용→ 확인→ 모의 자동→ 실전

스펙 몇 줄로 안전이 완성되진 않습니다. 권한을 천천히 엽니다. 강사도 겁납니다 — 그래서 천천히.

끝 / 다음

실전 매매·심화는 3~4회차로 이어집니다. 오늘 만든 연결과 에이전트가 그 출발점입니다.
